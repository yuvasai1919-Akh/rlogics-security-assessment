# Finding -> remediation examples

Fill in the "evidence" lines with file names from **your own** run in `evidence/runs/...`.

## 1. SQL injection (SAST + DAST)
| | |
|---|---|
| Tool | Semgrep (`lab-sql-built-from-string`, registry Flask/SQL rules); ZAP active scan (optional) |
| Severity / why it matters | High. Unauthenticated endpoint, attacker-controlled input changes the query -> data disclosure/tampering |
| Before | `query = "SELECT ... WHERE name = '%s'" % name` then `db.execute(query)` |
| After | `db.execute("SELECT ... WHERE name = ?", (name,))` plus input length check |
| Verification | Re-run Semgrep: finding gone. Manual: `curl "http://127.0.0.1:8000/user?name=' OR '1'='1"` returns all users on the vulnerable build, empty list on remediated |
| Why not suppress | Not a false positive; user input genuinely reaches the SQL string |
| Evidence | `semgrep.json` (before) vs (after) |

## 2. Outdated dependencies with known CVEs (SCA)
| | |
|---|---|
| Tool | Trivy fs/image |
| Before | `Flask==2.0.1`, `Werkzeug==2.0.1`, `Jinja2==3.0.1`, `requests==2.25.1`, `urllib3==1.26.4` ... (several High/Medium CVEs with fixed versions) |
| After | Flask 3.1.x, Werkzeug 3.1.x, requests 2.32.4+, PyYAML 6.x |
| Gate behaviour | `scan_gate.py --fail-on HIGH --only-fixable` -> exit 1 before, exit 0 after (if no new fixable High) |
| Notes | Fixed versions move over time; re-run Trivy on your date. Distinguish "has a fix" (block) from "no fix" (exception/mitigation) |
| Evidence | `trivy-fs.json`, `gate-fs.md` before/after |

## 3. Container runs as root (misconfiguration)
| | |
|---|---|
| Tool | Trivy misconfig (Dockerfile check: image user should not be root) |
| Before | No `USER` instruction |
| After | `useradd --uid 10001` + `USER 10001`, HEALTHCHECK added, copy only `app.py` |
| Why | Root in container + any escape/kernel bug = host-level impact; also ties to Kubernetes `runAsNonRoot` admission rule |

## 4. Secret baked into the image (secret scanning)
| | |
|---|---|
| Tool | Trivy secret scanner (fs and image) |
| Before | `COPY . .` copies `leaked_config.py` (synthetic token generated by `make plant-secret`) into the image |
| After | Remediated Dockerfile copies only `app.py`; secrets come from the platform (OpenBao/K8s Secret) at runtime |
| Key lesson | Removing a leaked secret from the latest commit is **not** remediation; rotate/revoke it and assume it was exposed. Gate row #1 blocks with no exception |

## 5. Unsafe deserialisation / weak hash / debug mode (SAST)
`yaml.load(..., Loader=yaml.Loader)` -> `yaml.safe_load`; MD5 password hash -> `generate_password_hash`
(salted, slow); `debug=True` -> no debug flag, run under gunicorn.
